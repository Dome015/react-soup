# Example pages and patterns

Every child directory contains a React example and its own `AGENTS.md`. These examples demonstrate composition and appropriate placement of components. They are reference code for agents building a host app and are not runtime imports of the library. Storybook exposes them in `Examples` stories. Use the standard layout primitives and tokens; do not duplicate component styles or introduce literal CSS values in examples.

Examples cover settings, authentication, CRUD listing, search with filters, empty state, confirmation, destructive action, page header, sidebar navigation, table toolbar, pagination, profile, dashboard, charts, project workspace, team management, and document review. Start from the closest example when building a new screen. Use Project Workspace when filters, sorting, pagination, editing, and deletion must work together. Use Team Management for peer views, invitations, role changes, and a confirmed revoke action. Use Document Review for file selection, real local progress, and a blocked repeat action while work runs. Settings Form shows native date and time Inputs beside a separate timezone. Storybook variants expose meaningful starting modes.
Use a direct heading and concise supporting copy. Do not use eyebrow labels above headings or uppercase accent labels on statistics.
Shared example element resets in `examples.css` have low specificity so Field, Dialog, Card, and other component internals keep their own spacing and type rules. Use layout primitives and token-backed example classes for local composition.
